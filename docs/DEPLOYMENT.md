# Развёртывание и восстановление

Приложение — обычный Go HTTP-сервер. Оно слушает `PORT`, встраивает в бинарный файл оформление и резервные данные, не требует базы данных или записи на диск.

## Render

В корне находится `render.yaml`: Go-сервис, бесплатный тариф, сборка `go build -trimpath -o bin/tour-track .`, запуск `./bin/tour-track`, проверка `/readyz`. Переменная `GO_VERSION` фиксирует версию компилятора 1.26.8. Такой формат описан в [официальном справочнике Blueprint](https://render.com/docs/blueprint-spec).

Для новой публикации нужен доступ к аккаунту Render и Git-репозиторию с этой версией. Подключите репозиторий, выберите Go, проверьте команды из конфигурации и создайте сервис. При обновлении существующего сервиса сохраняйте его домен и меняйте исходный commit/ветку на проверенную версию проекта.

Ранее у владельца существовал адрес `https://tour-track.onrender.com`. При первоначальной проверке 7 ноября 2026 года он отвечал 503. Это не свидетельство успешной публикации новой версии. Фактический итог текущей публикации записывается в [TEST_REPORT.md](TEST_REPORT.md).

Проверка после размещения:

```sh
curl -f https://ВАШ-ДОМЕН/healthz
curl -f https://ВАШ-ДОМЕН/readyz
curl -f https://ВАШ-ДОМЕН/api/artists
curl -i -X POST https://ВАШ-ДОМЕН/api/refresh
curl -f https://ВАШ-ДОМЕН/api/status
```

Главная страница и `/artists/1` должны открываться. При неработающем внешнем API ожидается 200 с резервным каталогом и заметным предупреждением. `stale: true` в состоянии означает, что живые данные не подтверждены, а не поломку HTTP-сервера.

## Другой сервер

На машине для сборки выполните:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o tour-track .
```

Перенесите бинарный файл на Linux amd64 и запустите с `PORT=8080`. Перед ним можно поставить штатный reverse proxy хостинга с HTTPS. Для другого процессора измените `GOARCH`. `Dockerfile` даёт альтернативную контейнерную сборку; сборка этого образа отдельно не считается проверенной без фактического запуска Docker.

## Что происходит при отказе API

При старте доступен встроенный архив. Работник сразу пробует обновление, затем повторяет его каждые пять минут. Четыре запроса получают общий предел 12 секунд и индивидуальные HTTP-тайм-ауты. Частичный результат не заменяет каталог. Повторный ручной запуск доступен через 10 секунд после завершения прошлого.

После успешного обновления каталог хранится в памяти процесса. Перезапуск возвращает встроенный архив до следующего успеха API. Долговременная запись на диск намеренно не используется: она не требуется ТЗ и не доступна постоянно на некоторых бесплатных хостингах.

Для восстановленного или совместимого API задайте `API_BASE_URL`. Адрес должен оканчиваться базовым путём, например `https://example.org/api`; программа сама добавляет `/artists`, `/locations`, `/dates`, `/relation`. Адреса из полученного JSON не используются для сетевых запросов. Не помещайте токен в URL.

## Git и секреты

Gitea назначения: `https://01.tomorrow-school.ai/git/ysoltamb/tour-track`.

Если терминальный Git ещё не авторизован, из корня выполните `./scripts/connect-gitea.sh`. Введите токен с доступом к нужному репозиторию в скрытом приглашении. Скрипт хранит его только в памяти `git credential-cache` на час; токен не попадает в URL, исходники или историю команд. Вход в веб-интерфейс Gitea сам по себе не настраивает Git в WSL.

После публикации проверьте равенство локального commit и `git ls-remote origin refs/heads/main`. Локальную рабочую папку можно удалять только после сохранения всех файлов и подтверждения удалённого commit. Архивная копия ТЗ вне проекта принадлежит пользователю и этой очисткой не затрагивается.
