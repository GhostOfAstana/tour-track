# tour-track

`tour-track` — учебный музыкальный каталог на Go для Tomorrow School / 01-Edu. Он объединяет сведения об артистах, местах выступлений и концертных датах, а затем показывает понятную оценку гастрольной активности. Цель проекта — продемонстрировать работу с JSON API, клиентом и сервером, обработкой ошибок, параллельными задачами и проверяемыми правилами классификации.

Интерфейс, комментарии и документация написаны по-русски. Названия артистов, исходные даты, места и обязательные метки активности сохраняются в формате ТЗ. Приложение использует только стандартную библиотеку Go. База данных, npm, API-ключи и сторонние Go-пакеты не нужны. Фотографии из Wikimedia Commons встроены локально; автор и лицензия указаны на странице артиста и в [перечне изображений](internal/seed/IMAGES.md).

## Запуск

Нужен Go 1.24 или новее. Из папки проекта:

```sh
go run .
```

Откройте http://localhost:8080. Остановка — `Ctrl+C`. Для запуска уже собранного файла исходники и Go не требуются: HTML, CSS, JavaScript и резервный каталог встроены в исполняемый файл.

```sh
go build -trimpath -o bin/tour-track .
./bin/tour-track
```

На проверяемом API https://groupietrackers.herokuapp.com/api все четыре раздела возвращали HTTP 404 **7 ноября 2026 года**. Поэтому приложение содержит проверенный архив всех 52 артистов. При запуске он доступен сразу; фоновая задача пытается получить живые данные. Предупреждение на странице явно сообщает, когда свежие данные не подтверждены. Источник, контрольные суммы и ограничения архива описаны в [PROVENANCE.md](internal/seed/PROVENANCE.md). Это исторические сведения, а не расписание актуальных гастролей.

## Что можно сделать

- Найти артиста по имени, участнику, месту, году основания или дате первого альбома.
- Отфильтровать каталог по активности, отсортировать по имени, баллам или году.
- Открыть карточку с составом группы, первым альбомом, исходными локациями, датами и связями «место → даты».
- Проверить расчёт баллов по исходным числам на странице артиста.
- Запустить обновление кнопкой: браузер отправляет POST, сервер ставит задание в канал, отдельная горутина загружает четыре части API. Браузер проверяет состояние, пока работа не завершится.

Поиск и просмотр работают без JavaScript. Подробное описание интерфейса — [docs/INTERFACE.md](docs/INTERFACE.md).

## Как считается активность

```text
стаж = текущий год сервера − год начала деятельности
баллы = страны × 2 + записи дат × 3 + min(10, стаж / 5)
```

Деление на 5 целочисленное. Страны извлекаются из `locations`, а число концертов — из массива `dates`. Повторные записи дат не удаляются: в один день возможны разные выступления. Стаж пересчитывается при каждом HTTP-запросе, даже для сохранённых исходных данных.

| Баллы | Метка |
| --- | --- |
| 0–10 | Emerging |
| 11–25 | Active |
| 26–40 | Established |
| 41 и больше | Legendary |

Пример ТЗ: `5 × 2 + 8 × 3 + min(10, 30 / 5) = 40`, метка — `Established`.

Бонус **Rising Star** выдаётся, если среднее число концертов за последние два года **строго больше** среднего за карьеру, умноженного на 1,5. Скользящее окно включает начальную дату и сегодняшний день; будущие и неразбираемые даты в недавние концерты не попадают. При нулевом стаже метка не выдаётся. На историческом снимке в 2026 году Rising Star может отсутствовать: искусственные новые концерты не добавляются.

## Надёжность

Четыре ответа API загружаются параллельно и связываются по `id`. Новый каталог публикуется только после успешной проверки всех частей. Ошибка, неполный JSON, несовпадающие ID, слишком большой ответ и тайм-аут сохраняют предыдущий полный каталог. Повторные клики объединяются в одно задание; после завершения действует пауза 10 секунд. Автообновление запускается раз в пять минут.

Есть ограничения времени и объёма HTTP, экранирование HTML, запрет выполнения inline-скриптов, проверка источника POST-запроса, обработка ошибок и штатное завершение по SIGTERM. Ответы об ошибках имеют корректные коды 400, 403, 404, 405, 413, 414, 429, 500 и 503. Невозможно гарантировать выживание при исчерпании всей памяти машины, аварии ОС или отключении хостинга; границы защиты объяснены в [справочнике аудитора](docs/AUDITOR_FAQ.md).

## Настройки и размещение

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `8080` | TCP-порт от 1 до 65535 |
| `HOST` | пустая строка | Все сетевые интерфейсы; `127.0.0.1` — только локальный доступ |
| `API_BASE_URL` | `https://groupietrackers.herokuapp.com/api` | Базовый адрес совместимого API без токена и параметров |

`GET /healthz` проверяет, что процесс отвечает. `GET /readyz` возвращает 200, если каталог доступен, и 503, если данных нет. В JSON состояния видно, используется ли архив. `GET /api/artists`, `GET /api/artists/{id}` и `GET /api/status` позволяют проверить результат без HTML. `POST /api/refresh` принимает задание и возвращает 202.

Развёртывание описано в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Наличие конфигурации развёртывания само по себе не подтверждает, что новая версия опубликована: фактический статус указан в отчёте проверок.
